# Lex.uz Legal RAG

Высокоточная юридическая Retrieval-Augmented Generation (RAG) система для полнотекстового и семантического поиска по законодательной базе Республики Узбекистан ([Lex.uz](https://lex.uz)).

---

## 🌟 Ключевые возможности

- **Билингвальный поиск и паритет (UZ / RU):** Поддержка узбекского (латиница и кириллица) и русского языков с сохранением структурного паритета между оригиналом и официальным переводом.
- **Орфографическая нормализация узбекского языка:** Канонизация всех типов апострофов (`‘`, `’`, `ʻ`, `ʼ`, `` ` `` $\rightarrow$ `'`), фонетический транслитератор кириллицы в официальную латиницу с правилами юридической терминологии (`кц` $\rightarrow$ `ks`, контекстная `е`, исключения твердого/мягкого знаков).
- **Специализированный парсинг DOM Lex.uz:**
  - **Архетип A:** Структурированные законы и кодексы (`.ACT_TEXT`, `.CLAUSE_DEFAULT`), точное извлечение статей (`modda`), пунктов (`band`), частей и преамбул.
  - **Архетип B:** Неструктурированные постановления, регламенты, перечни, тарифы с плоскими абзацами.
  - **Табличный процессор:** Разбор сложных таблиц с `rowspan`/`colspan`, сквозное наследование шапок, нарезка гигантских таблиц на смысловые слайсы в формате Markdown.
- **Семантический граф и метаданные:** Сохранение абзацных якорей (`lx_mo`), цитат и ссылок на связанные документы (`/docs/...`), иерархических хлебных крошек (`breadcrumbs`) и классификатора ОКОЗ.
- **Двухэтапный гибридный поиск:**
  - **Этап 1 (Dense + Sparse BGE-M3):** Параллельный плотный семантический поиск и разреженный лексический поиск в векторной базе **Qdrant** с объединением рангов через **RRF (Reciprocal Rank Fusion)**.
  - **Этап 2 (BGE-Reranker-v2-m3):** Кросс-энкодер реранкинг топ-кандидатов с фильтрацией по метаданным (язык, классификатор ОКОЗ, тип нормы, документ).
- **Отказоустойчивая индексация:** Пакетная векторизация на GPU/CPU с транзакционными чекпоинтами, предотвращающая потерю прогресса.

## 🚀 Быстрый старт

### 1. Требования

- **Python:** `>= 3.12`
- **Docker & Docker Compose:** для запуска Qdrant
- Рекомендуется GPU с поддержкой CUDA (для быстрого инференса BGE-M3 и BGE-Reranker)

### 2. Установка зависимостей

С использованием `uv`:
```bash
uv sync
```

Или через классический `pip` в виртуальном окружении:
```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .
```

### 3. Запуск векторной базы данных Qdrant

```bash
docker compose up -d
```
Панель управления Qdrant будет доступна по адресу: `http://localhost:6333/dashboard`.

## 🛠 Использование CLI (`lexuz`)

Система предоставляет единый интерфейс командной строки через `main.py` или команду `lexuz`.

```bash
python main.py --help
```

### 1. Парсинг сырых документов
Пакетный разбор выкачанных `.html.gz` файлов в структурированные чанки:
```bash
python main.py parse --archetype a --raw-dir data/raw_html --output data/chunks_archetype_a.jsonl.gz
```

### 2. Аудит корпуса
Проверка валидности чанков, отсутствия остаточного мусора, баланса языков и распределения длин:
```bash
python main.py audit --chunks data/chunks_archetype_a.jsonl.gz
```

### 3. Индексация в Qdrant
Пакетная векторизация корпуса моделью `BAAI/bge-m3` и загрузка в Qdrant с чекпоинтами:
```bash
python main.py index \
  --input data/chunks_archetype_a.jsonl.gz data/chunks_archetype_b.jsonl.gz \
  --collection lexuz_collection \
  --batch-size 64 \
  --encode-batch-size 32 \
  --device cuda
```

### 4. Гибридный поиск
Высокоточный поиск с фильтрацией по метаданным:
```bash
python main.py search "mehnat shartnomasini bekor qilish tartibi" --lang uz --top-k 5
```

Поиск с фильтрацией по коду ОКОЗ или типу нормы:
```bash
python main.py search "порядок прекращения трудового договора" --lang ru --okoz "05" --unit-type article
```
